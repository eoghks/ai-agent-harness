# 에이전트 보고서 열람

보고서 폴더: `<사용자 홈>\wiki\에이전트보고` (위키 폴더가 없는 머신이면 `<사용자 홈>\.claude\reports`).
인덱스: `_index.md` — 캐시일 뿐이다. 인덱스가 실제 파일과 어긋나면 각 보고서 frontmatter를
Grep으로 스캔해 재생성한다.

## 동작

- **`/reports`** (인수 없음) 또는 "보고서 보여줘" → 목록을 보여준다.
  미열람(`read: false`)을 위에, 그 아래 최근 읽음 5개. 각 줄 형식:
  `번호. [⬜|✅] MM-DD HH:mm [에이전트] 작업명 — 상태: 한 줄 요약`
  status가 차단/needs-input인 항목은 목록 맨 위에 경고 표시(⚠)와 함께 올린다.
- **`/reports <번호|키워드>`** 또는 "N번 열어줘", "리뷰 결과 보여줘" → 해당 보고서 본문 전문을
  채팅에 출력하고 frontmatter `read: false → true`로 갱신, 인덱스 ⬜→✅ 갱신.
  키워드면 title/summary에서 검색해 1건이면 바로 열고, 여러 건이면 후보 목록을 보여준다.
- **`/reports del <번호>`** 또는 "N번 삭제해줘" → 해당 보고서 파일을 삭제하고 인덱스에서 제거한다.
  삭제 전 대상 파일명을 보여주고 확인을 받는다.
- **`/reports clean`** 또는 "오래된 보고서 정리해줘" → 정리:
  1. `read: true` 이고 30일 경과한 파일을 정리 후보로 모은다.
  2. 후보 목록을 보여주고 **확인 후** 삭제한다 — 자동 삭제는 하지 않는다.
  3. 인덱스를 현재 남은 파일 기준으로 재생성한다.

## 규칙

- 보고서 본문은 수정하지 않는다 — 변경은 frontmatter `read` 필드와 인덱스(`_index.md`)뿐이다.
- 폴더가 없으면 생성한다 (첫 사용 머신). 위키 폴더 자체가 없으면 `.claude\reports`를 본다.
- 위키는 git을 사용하지 않는다 — 파일 수정만 하고 어떤 git 명령도 실행하지 않는다.
- 미열람이며 차단/needs-input인 보고서가 있는데 사용자가 다른 요청을 하면, 요청 처리 후 말미에
  "미열람 차단/입력대기 보고서 N건" 한 줄을 덧붙인다.
- 목록 조회 시 읽음 처리된·30일 경과 보고서가 있으면 "정리할까요?" 한 줄을 덧붙여 제안한다(강제 삭제 금지).
