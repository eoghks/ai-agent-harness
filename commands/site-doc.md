현재 `site/*` 브랜치의 커밋을 분석해서 `docs/site-custom/` 문서를 생성하거나 갱신하세요.

인수: $ARGUMENTS

---

## 인수 파싱

`$ARGUMENTS`에서 커밋 해시 목록과 옵션을 분리하세요.

- `--force`: 기존 문서가 있으면 이력을 유지하지 않고 전체 재작성
- 그 외 토큰은 모두 커밋 해시로 취급
- 해시가 없으면 HEAD를 사용

| 입력 예시 | 해시 목록 | force |
|-----------|-----------|-------|
| (없음) | [HEAD] | false |
| `abc1234` | [abc1234] | false |
| `--force` | [HEAD] | true |
| `abc1234 def5678` | [abc1234, def5678] | false |
| `abc1234 def5678 --force` | [abc1234, def5678] | true |

---

## 실행 순서

**1단계: 환경 확인**

```bash
git rev-parse --abbrev-ref HEAD
```

브랜치가 `site/`로 시작하지 않으면 "site/* 브랜치에서만 실행 가능합니다." 안내 후 중단하세요.

**2단계: 커밋 목록 수집 및 시간순 정렬**

각 커밋의 Unix timestamp를 조회해 오래된 순(oldest first)으로 정렬하세요.

```bash
git log -1 --format="%at %H %s" <hash>   # 각 해시마다 실행
```

커밋이 존재하지 않으면 해당 해시를 건너뛰고 경고를 출력하세요.

**3단계: 커밋별 처리 (오래된 순)**

정렬된 커밋 목록을 순서대로 처리합니다. 각 커밋에 대해:

**3-1. 커밋 정보 수집**

```bash
git log -1 --pretty=format:"%s%n%b%n%H%n%an%n%ad" --date=format:"%Y-%m-%d" <hash>
git show <hash> --name-only --format=
```

변경 파일을 확장자 우선순위 순으로 정렬하세요: `.java` > `.js` > `.ts` > `.vue` > `.sql` > `.xml` > `.yml`

변경 파일이 없으면 해당 커밋을 건너뜁니다.

**3-2. 커밋 메시지 파싱**

형식: `type(scope): [사이트명] 제목`

- `(scope)`: 있으면 즉시 파일명으로 사용
- `[사이트명]`: 없으면 `docs/site-custom/*/OVERVIEW.md`에서 현재 브랜치로 사이트명 검색
- 사이트명을 확정할 수 없으면 사용자에게 질문하세요.

**3-3. diff 수집**

```bash
git show <hash> -- <우선순위순_파일들>
```

**3-4. 스코프 결정**

- 커밋 메시지에 `(scope)` 있음 → 그대로 사용
- 없음 → diff와 기존 문서 목록 분석 후 추론
- 추론 불가 → 사용자에게 스코프 명시 요청

```bash
ls docs/site-custom/<사이트명>/ 2>/dev/null || echo "(없음)"
```

**3-5. 문서 파일 결정**

1. 스코프 있음 → `<스코프>.md`
2. 스코프 없음 + 기존 연속 커밋 → 기존 파일
3. 스코프 없음 + 신규 → Claude가 기능 단위 제목으로 결정

**3-6. 문서 작성**

- `--force` **없음** + 기존 파일 있음 → 이력 항목 추가 후 시간순 재정렬 (아래 규칙)
- `--force` **있음** + 기존 파일 있음 → 전체 재작성
- 기존 파일 없음 → 신규 생성

**신규 문서 형식:**

```markdown
# [사이트명] 기능제목

- **사이트:** 사이트명
- **유형:** commitType
- **최초 작성:** YYYY-MM-DD

---

## 고객 요구사항

diff에서 추론한 비즈니스 요구사항 1~3문장

---

## 기능 요약

기술적 기능 요약 1~2문장

---

## 커스텀 클래스 분석

### 클래스명 (상속/구현 있는 경우)

| 항목 | 내용 |
|------|------|
| **파일** | `전체경로` |
| **상속/구현** | extends/implements 관계 |
| **커스텀 범위** | 커스텀된 메서드/영역 |

#### 기능 설명

무엇을 왜 바꿨는지 2~4문장

#### 표준 대비 변경점

| 처리 항목 | 표준 방식 | 커스텀 방식 |
|-----------|-----------|------------|
| ... | ... | ... |

### 클래스명 (신규 구현 클래스)

| 항목 | 내용 |
|------|------|
| **파일** | `전체경로` |
| **커스텀 범위** | 커스텀된 메서드/영역 |

#### 기능 설명

무엇을 왜 바꿨는지 2~4문장

---

## 변경 이력

### YYYY-MM-DD — TYPE `hash` (author)

> 최초 개발

- `클래스명`: 커스텀 범위
```

**기존 문서에 이력 추가 시 정렬 규칙:**

`## 변경 이력` 아래의 모든 `### YYYY-MM-DD` 항목을 날짜 기준 **내림차순(최신이 위)**으로 재정렬하세요.

여러 커밋을 처리할 때는 각 커밋 처리 후가 아니라 모든 커밋 처리가 끝난 뒤 한 번만 재정렬하세요.

이력 항목 형식 (새 항목):
```markdown
### YYYY-MM-DD — TYPE `hash` (author)

**`클래스명`**
- 범위: 커스텀된 메서드/영역
- 내용: 변경 내용 설명
```

**4단계: OVERVIEW.md 갱신**

모든 커밋 처리 후 `docs/site-custom/<사이트명>/OVERVIEW.md`를 갱신하세요. 변경된 문서가 여러 개면 한 번에 반영합니다.

```markdown
# [사이트명] 사이트 커스텀 개요

- **사이트명:** 사이트명
- **브랜치:** `현재브랜치`
- **마지막 갱신:** YYYY-MM-DD

---

## 커스텀 기능 목록

| 기능명 | 유형 | 최초 작성 | 마지막 수정 | 상세 문서 |
|--------|------|-----------|-------------|-----------|
| ... | ... | ... | ... | [문서](./파일명.md) |
```

**5단계: 문서 자동 커밋 (수동 재생성 경로 한정)**

> 커밋 주체 단일화 안내
> site/* 브랜치에 **코드 커밋**이 발생하는 경우의 문서 커밋은 PostToolUse 훅
> (`hooks/site-custom-doc-update.js`)이 문서 두 개(상세 문서·OVERVIEW.md)만
> 경로 한정으로 자동 처리합니다. 따라서 그 경로에서는 이 스킬이 커밋하지 않습니다.
>
> 이 5단계 커밋은 코드 커밋 없이 `/site-doc`를 직접 실행해 **과거 커밋 문서를 재생성**하는
> 경우에만 동작합니다. 이때는 새 코드 커밋이 없어 훅이 발동하지 않으므로 스킬이 커밋합니다.
> (스킬의 이 커밋은 문서만 담으므로, 훅이 발동하더라도 코드 변경 파일이 없어 훅은 즉시 종료하여
>  이중 커밋이 발생하지 않습니다.)

생성·갱신된 문서를 경로 한정으로 즉시 커밋하세요. 확인을 구하지 말 것.
다른 변경 사항을 쓸어 담지 않도록 반드시 docs/site-custom/ 경로로 한정합니다.
신규(untracked) 문서는 `git commit -- <경로>`만으로는 pathspec이 잡지 못해 커밋이 실패하므로,
같은 경로 한정으로 `git add -- <경로>`를 먼저 한 뒤 `git commit -- <경로>`로 파일 지정 커밋합니다.
(경로 한정 add라 사용자가 다른 곳에 해둔 스테이징은 건드리지 않습니다.)

```bash
git add -- docs/site-custom/
git commit -m "docs(<스코프>): [<사이트명>] 커스텀 문서 갱신" -- docs/site-custom/
```

- 스코프 1개 처리 시: `docs(임시겸직): [농심] 커스텀 문서 갱신`
- 여러 스코프 처리 시 스코프 생략하고 설명에 나열: `docs: [농심] 커스텀 문서 갱신 (임시겸직, 결재선)`

**6단계: 완료 보고**

처리된 커밋 수, 생성/갱신된 파일 목록, `--force` 여부, 문서 커밋 해시를 출력하세요.
예) "커밋 3개 처리 → 임시겸직.md 갱신, 결재선.md 신규 생성 → docs 커밋 a1b2c3d"
