### 1.2 파일명 규칙

```
agent-reports\YYYYMMDD-HHmmss_<에이전트>_<작업슬러그>.md
예) 20260612-143205_implementer_그룹규칙-표현식-복원-수정.md
```

- 타임스탬프 초 단위 + 에이전트명 → 동시 완료 충돌 사실상 차단 (같은 초에 같은 에이전트 둘이면 `-2` 접미)
- 작업슬러그: 한글 허용, 공백→`-`, 30자 이내 (Windows 경로 길이 여유 확보)
- 아카이브: `agent-reports\archive\` 하위로 이동 (4.3 정리 정책)


- `severity: critical`은 에이전트가 critical 발견·차단 이슈·질문 복귀 시 설정 (4.2 예외 규칙과 연동).

## 2. 생성 메커니즘 — 3안 비교

### A안: 에이전트 프롬프트 규약 (에이전트가 직접 저장)

각 에이전트 .md의 "보고 형식" 섹션을 개정: 보고 전문을 위 포맷으로 파일 저장 → 최종 반환은 `한 줄 요약 + 경로 + status`만.

- 장점: **메인 세션 토큰 절약이 가장 큼** — 보고 전문이 메인 컨텍스트에 아예 안 들어옴(서브에이전트 결과 = 한 줄). 보고 품질도 최상 — 작성 당사자가 전문을 무손실로 기록. 동시 완료에도 각자 자기 파일을 써서 경합 없음.
- 단점: 에이전트가 규약을 누락할 수 있음(특히 오류로 조기 종료 시). **analyzer·code-reviewer·verifier에 Write 도구 추가 필요** — "코드를 고치지 않는다" 원칙과의 긴장은 "agent-reports 폴더에만 Write 허용"을 프롬프트에 명시해 완화.
- 구현 난이도: 낮음 (md 텍스트 수정 4건).

### B안: 메인 세션 규약 (메인이 받아서 저장)

완료 알림 수신 시 메인 세션이 결과 전문을 파일로 저장하고 채팅엔 한 줄만 출력.

- 장점: 에이전트 무변경, 도구 권한 변경 불필요. 메인이 항상 개입하므로 형식 일관성 보장.
- 단점: **전문이 어차피 메인 컨텍스트로 들어와 토큰 절약 효과 없음** — 줄어드는 건 채팅 출력뿐. 메인이 저장하며 재구성하다 정보 누락 가능. 동시 완료 다발 시 메인 턴 하나에서 여러 파일 저장 — 누락 위험 증가.
- 구현 난이도: 가장 낮음 (CLAUDE.md·스킬 문구만).

### C안: SubagentStop 훅 자동 캡처

Claude Code 훅 이벤트 `SubagentStop`(서브에이전트 종료 시 발화)으로 트랜스크립트에서 최종 메시지를 추출·저장하는 스크립트.

- 장점: 규약 의존 제로 — 누락 구조적으로 불가능. 에이전트·메인 토큰 비용 0.
- 단점/불확실성 (명시): SubagentStop 훅 입력에 서브에이전트 트랜스크립트 경로가 포함되는 것으로 알려져 있으나, **(1) run_in_background로 띄운 Task에도 발화하는지, (2) JSONL 내부 구조가 버전 간 안정적인지 검증 못 함 — 불확실.** 또한 훅 스크립트는 작업명·한줄요약·status 같은 메타데이터를 만들 수 없어(LLM 아님) frontmatter 품질이 떨어짐. 마지막 메시지 = 보고 전문이라는 보장도 없음(질문 복귀·오류 종료). 구현·유지보수 난이도 최고.

### 비교표

| | A안 (에이전트) | B안 (메인) | C안 (훅) |
|---|---|---|---|
| 메인 토큰 비용 | **최소** | 변화 없음 | 최소 |
| 누락 위험 | 중 (규약 미준수) | 중 (다발 시) | **최소** (단, 동작 보장 불확실) |
| 보고 품질/메타데이터 | **최상** | 상 (재구성 손실 가능) | 하 (요약·메타 생성 불가) |
| 구현 난이도 | 낮음 | 최저 | 높음 + 검증 필요 |

### 추천: **A안 기본 + B안 폴백 (하이브리드)**

- 에이전트가 저장·한줄 반환 (A). 메인 세션은 알림 수신 시 **반환된 경로의 파일 존재를 확인** — 없거나 에이전트가 전문을 그대로 반환했으면 메인이 받은 내용을 저장하고 한 줄만 출력 (B 폴백).
- A의 토큰·품질 이점을 취하면서 A의 유일한 약점(누락)을 B가 막는다. C안은 추후 SubagentStop 동작이 검증되면 "이중 안전망"으로 재검토.

## 4. 알림 정책

### 4.1 채팅 한 줄 요약 형식 (완료 알림 수신 시 메인 세션 출력)

```
✅ [implementer] 그룹규칙 표현식 복원 수정 — 성공: paramValue 27개 초과 깨짐 수정, 테스트 3건 통과 (보고서: ~\.claude\agent-reports\20260612-143205_implementer_그룹규칙-표현식-복원-수정.md → /reports 1)
```

- 구성: 상태 아이콘 + [에이전트] 작업명 — 상태: 요약 1문장 + 경로(또는 `/reports N` 안내). **2줄 초과 금지.**
- /work 사이클 중이면 한 줄 출력 후 다음 단계 위임을 이어간다 (기존 흐름 유지).
- /work 6단계 "통합 보고"는 유지하되 **각 단계 보고서 경로 목록 + 단계별 1줄 요약**으로 압축 — 전문 인용 금지.

### 4.2 예외 — 즉시 채팅 표출 (문서로만 두지 않는다)

다음은 파일 저장과 **동시에** 해당 내용을 채팅에 바로 출력한다:

1. **critical 발견** (code-reviewer critical, 보안 이슈) — critical 항목 전문을 채팅에.
2. **차단 이슈** — 빌드 실패, verifier 불합격(기존 /work 5단계 "즉시 사용자 보고" 원칙과 일치).
3. **사용자 입력 필요** — implementer 질문 복귀, 권한·결정 대기. 질문 목록을 채팅에.

에이전트는 이 경우 frontmatter `severity: critical`을 설정하고, 한 줄 반환에 `⚠` 표시 + 핵심 내용을 포함한다. "요약만 보고 critical을 놓치는" 사고를 구조적으로 차단하는 규칙이다.

1. **저장 위치 변경**: 설계서는 전역 `~\.claude\agent-reports\`를 채택했으나, 최종은 **위키 `~\wiki\에이전트보고\`** 로 확정.
